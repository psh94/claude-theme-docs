# 보안 규칙 - 민감 데이터 보호

> 민감한 데이터의 노출을 방지하기 위한 규칙입니다.

---

## 1. 접근 금지 파일

다음 패턴의 파일은 **절대 읽거나 내용을 출력하지 않습니다**:

```
**/.env
**/.env.*
**/*.p12
**/*.jks
**/*.pem
**/*.key
**/credentials*
**/secrets*
{프로젝트별 환경 설정 파일 패턴}
```

---

## 2. 마스킹 대상 패턴

다음 정보가 코드나 출력에 포함되지 않도록 합니다:

| 유형 | 예시 |
|------|------|
| DB 접속 정보 | `{protocol}://{host}:{port}/{db}` |
| DB 비밀번호 | `{db.password}=****` |
| API 키/시크릿 | `api-key: sk-****` |
| JWT 시크릿 | `jwt.secret=****` |
| OAuth 자격증명 | `client-secret=****` |
| 인증 토큰 | `Bearer ****` |
| SSH 키 | `-----BEGIN RSA PRIVATE KEY-----` |

---

## 3. 예외 조건

사용자가 **명시적으로** 특정 파일의 검토를 요청한 경우에만 접근하되,
출력 시 민감 값은 마스킹(`****`)하여 표시합니다.

---

## 4. 코드 작성 시 보안 수칙

- SQL: 반드시 파라미터 바인딩 사용, 문자열 결합 지양
- XSS: 사용자 입력값 이스케이프 처리
- CSRF: 프레임워크의 CSRF 방어 기능 활용
- 하드코딩 금지: 비밀번호, API 키를 소스코드에 직접 작성하지 않음
