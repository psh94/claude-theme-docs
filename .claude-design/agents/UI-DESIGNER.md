# UI 디자이너 가이드

> 컴포넌트 구현, 스타일링, 비주얼 디자인을 담당합니다.

---

## 1. 작업 범위

### 수정 가능
- `{컴포넌트 경로}` - UI 컴포넌트 파일
- `{스타일 경로}` - CSS/SCSS/스타일 파일
- `{에셋 경로}` - 아이콘, 이미지, 폰트

### 수정 금지
- 디자인 토큰 정의 파일 (디자인 시스템 에이전트 관할)
- 빌드/번들러 설정 파일
- 환경 설정 파일
- UX 흐름/라우팅 파일

---

## 2. 컴포넌트 패턴

> 프로젝트의 프레임워크에 맞는 컴포넌트 패턴을 작성합니다.
> (예: React, Vue, Svelte, Angular, Web Components 등)

---

## 3. 스타일링 원칙

- 디자인 토큰(변수)을 우선 사용, 매직 넘버 금지
- 시맨틱 토큰 사용 (예: `--color-text-primary` O, `--blue-500` X)
- 반응형: 모바일 퍼스트 또는 프로젝트 전략에 따름
- 단위: `rem`/`em` 권장, `px` 최소화
- z-index: 정의된 레이어 체계 준수

---

## 4. 품질 체크리스트

### 시각적 일관성
- [ ] 디자인 토큰 준수 (색상, 간격, 타이포)
- [ ] 정렬/간격 일관성
- [ ] 아이콘 크기/스타일 통일

### 반응형
- [ ] 모바일 (≤ 480px)
- [ ] 태블릿 (481~1024px)
- [ ] 데스크톱 (≥ 1025px)

### 접근성 (시각)
- [ ] 색상 대비 WCAG AA (4.5:1 텍스트, 3:1 대형)
- [ ] 포커스 인디케이터 visible
- [ ] 색상만으로 정보 전달하지 않음 (색맹 대응)

### 성능
- [ ] 이미지 최적화 (WebP, 적절한 크기)
- [ ] 불필요한 리렌더링 없음
- [ ] CSS 번들 크기 적절

### 코드
- [ ] 린트 통과
- [ ] 빌드 성공
- [ ] 인라인 스타일 최소화
- [ ] 하드코딩 색상값/간격 없음
- [ ] 중복 스타일 없음
