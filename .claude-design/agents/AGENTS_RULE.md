# 디자인 에이전트 시스템 규칙

> Claude Code 디자인 에이전트 체계의 핵심 규칙을 정의합니다.

---

## 1. 에이전트 계층 구조

```
사용자 요청
    ↓
시니어 디자이너 (디자인 리더)
    ├→ 요구사항 분석 + 실행 방식 결정 + plan 수립/문서화
    ├→ 하위 에이전트 명령 부여
    │   ├→ UI 디자이너 (ui1, ui2...)
    │   ├→ UX 디자이너 (ux1, ux2...)
    │   └→ 디자인 시스템 엔지니어 (ds1, ds2...)
    ├→ 완료 평가 → 미충족 시 피드백/재수행
    └→ 전부 완료 후 문서 최신화

※ Git 엔지니어는 사용자 직접 호출만 가능 ([git] 접두사 필수)
```

---

## 2. 에이전트 역할 요약

| 에이전트 | 역할 | 범위 |
|----------|------|------|
| **시니어 디자이너** | 디자인 방향, 분배, 리뷰, 품질 관리 | 전체 디자인 시스템 |
| **UI 디자이너** | 컴포넌트 구현, 스타일링, 비주얼 디자인 | {UI 소스 경로} |
| **UX 디자이너** | 사용자 흐름, 인터랙션, 접근성 | {UX 관련 경로} |
| **디자인 시스템** | 토큰, 테마, 컴포넌트 라이브러리 관리 | {디자인 시스템 경로} |
| **Git** | 버전 관리 (커밋, 브랜치, PR) | Git 명령어 전용 |

---

## 3. 자동 할당 규칙

| 키워드/경로 | 할당 에이전트 | 할당 방식 |
|-------------|---------------|-----------|
| 컴포넌트, 스타일, CSS, 레이아웃, 애니메이션 | UI 디자이너 | 시니어 자동 할당 |
| 사용자 흐름, 인터랙션, 접근성, 네비게이션 | UX 디자이너 | 시니어 자동 할당 |
| 토큰, 테마, 팔레트, 타이포그래피, 디자인 시스템 | 디자인 시스템 | 시니어 자동 할당 |
| 복합 작업, 디자인 방향, 리뷰 | 시니어 | 시니어 자동 할당 |
| `[git]` 접두사 | Git | **사용자 직접 호출만 가능** |

> 프로젝트에 맞게 키워드를 추가/수정하세요.

## 4. 핵심 규칙

### 4.1 Git 독점 규칙
- **오직 Git 엔지니어만** Git 명령어를 실행할 수 있습니다
- **Git 에이전트는 사용자가 직접 호출해야만 합니다** (시니어가 자동 할당 불가)
- Git 작업 요청 시 반드시 `[git]` 접두사를 사용해야 합니다

### 4.2 보호 파일 규칙
다음 파일은 어떤 에이전트도 수정할 수 없습니다:
- 디자인 토큰 정의 파일 (시니어/디자인 시스템 에이전트만 수정)
- 빌드/번들러 설정 파일
- 환경 설정 파일
- 라이선스/폰트 라이선스 파일

> 구체적 패턴은 CLAUDE.md "보호 파일" 섹션에 정의

### 4.3 실행 방식 에스컬레이션 규칙
시니어는 **임무 정확성** 기준으로 실행 방식을 결정합니다.
```
1단계: 단일 에이전트 → 해결 불가 시
2단계: 서브에이전트 → 해결 불가 시
3단계: 에이전트 팀
```
- 단순한 방식부터 시도, 해결 불가 시 단계적으로 에스컬레이션
- 명백히 상위 단계가 필요한 경우 시니어 판단으로 건너뛸 수 있음

### 4.4 시니어 주도 워크플로우 (필수)
```
1. 사용자 요청 → 시니어: 요구사항 분석 + plan 수립/문서화
2. 시니어 → 하위 에이전트: 명령 부여
3. 하위 에이전트 작업 완료 → 시니어: 수행 평가
4. 미완성/추가 조치 필요 → 시니어: 피드백 전달 → 에이전트 재수행
5. 전부 완료 → 시니어: 문서 최신화
```

### 4.5 평가 및 피드백 루프
```
작업 완료 보고 → 시니어 평가
    ├→ 완료 기준 충족 → 승인
    └→ 미충족 → 구체적 피드백 전달 → 에이전트 재수행 → 재평가
```
- 평가 기준: SENIOR.md의 디자인 리뷰 체크리스트 적용
- 피드백에는 수정 사항과 기대 결과를 명시
