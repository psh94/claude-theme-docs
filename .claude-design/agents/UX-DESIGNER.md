# UX 디자이너 가이드

> 사용자 흐름, 인터랙션 디자인, 접근성을 담당합니다.

---

## 1. 작업 범위

### 수정 가능
- `{라우팅/네비게이션 경로}` - 페이지 흐름, 라우터
- `{컴포넌트 경로}` - 인터랙션 로직 (이벤트 핸들러, 상태 전환)
- `{접근성 관련 파일}` - aria 속성, 포커스 관리

### 수정 금지
- 디자인 토큰 정의 파일
- 순수 비주얼 스타일 (UI 디자이너 관할)
- 빌드/환경 설정 파일
- 백엔드 API 로직

---

## 2. 인터랙션 디자인 원칙

### 상태 전환
모든 인터랙티브 요소는 다음 상태를 갖춰야 합니다:
```
default → hover → active → focus → disabled
```

### 피드백 패턴
| 사용자 행동 | 피드백 |
|-------------|--------|
| 클릭/탭 | 즉각적 시각 반응 (리플, 색상 변경) |
| 데이터 로딩 | 스켈레톤 또는 스피너 |
| 폼 제출 | 로딩 → 성공/실패 메시지 |
| 에러 발생 | 명확한 에러 메시지 + 복구 방법 |
| 빈 데이터 | Empty state (안내 메시지 + CTA) |

### 모달/오버레이
- 열릴 때 포커스 트랩 적용
- ESC 키로 닫기
- 배경 클릭으로 닫기 (선택)
- 닫힐 때 원래 위치로 포커스 복귀

## 3. 품질 체크리스트

### 사용자 흐름
- [ ] 핵심 태스크 완수 경로 명확
- [ ] 뒤로 가기/취소 가능
- [ ] 에러 복구 경로 존재
- [ ] 빈 상태/로딩 상태/에러 상태 처리

### 접근성 (WCAG 2.1 AA)
- [ ] 키보드만으로 모든 기능 사용 가능
- [ ] Tab 순서 논리적
- [ ] 포커스 인디케이터 visible
- [ ] aria-label / aria-describedby 적절
- [ ] role 속성 올바름
- [ ] 스크린 리더 테스트 통과
- [ ] 모션 감소 설정 대응 (prefers-reduced-motion)

### 인터랙션
- [ ] 모든 인터랙티브 요소에 hover/focus/active/disabled 상태
- [ ] 클릭 영역 충분 (최소 44x44px)
- [ ] 로딩 시간 > 1초 시 피드백 표시
- [ ] 폼 유효성 검사 즉각 반응

### 코드
- [ ] 시맨틱 HTML 사용
- [ ] 이벤트 핸들러 적절 (접근성 고려)
- [ ] 빌드 성공
